# Story: 011-get-bill-detail-api

## User Story

**As a** supervisor / manager on web
**I want** an API to retrieve the detail of a specific conversion bill (phiếu chuyển đổi trạng thái)
**So that** the web UI can display the full record list for review

## Acceptance Criteria

- [ ] **Given** a valid `bill_code`, **When** I call the GET detail API, **Then** the response returns: `bill_code`, `staff_name`, `created_at`, and a list of conversion records
- [ ] **Given** the records list, **Then** each record includes: `sku`, `item_name`, `from_status`, `to_status`, `quantity`, `converted_at`
- [ ] **Given** the bill has only success records, **Then** the API returns only records with `state = success`
- [ ] **Given** a `bill_code` that does not exist, **Then** the API returns 404
- [ ] **Given** the caller is not authorized, **Then** the API returns 403

## Technical Notes

- Data source: `ConversionWorkSession` (status = completed, identified by `bill_code`) joined with `ConversionRecord` (state = success) joined with `ConversionTransaction` (for `converted_at`)
- `converted_at` = `ConversionTransaction.created_at` (time inventory was actually updated)
- Read-only endpoint; no state mutation
- Endpoint: `GET /conversion-bills/{bill_code}`

## Dependencies

### Requires
- 009-record-conversion-transaction (transaction records provide the `converted_at` timestamp)
- 010-get-bill-list-api (bill must exist — generated by commit)

### Enables
- 006-conversion-detail-web-page (frontend calls this API for detail page)

## Edge Cases

| Scenario | Expected Behavior |
|----------|-------------------|
| Bill with 0 success records (edge case) | Response with empty records list (200 OK) |
| Very large bill (100+ records) | Full list or paginated — confirm with product |

## Out of Scope
- Filtering or searching records within a bill
- Exporting to CSV / Excel
- Editing or reversing conversions
